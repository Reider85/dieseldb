# Промпты на исправление движка (выполняются следующими, после промпта 10)

Эти промпты исправляют баги движка, которые фиксирует количественный тест `QuantitativeTest` (`test/diesel/QuantitativeTest.java`). Тест проверяет, что каждый запрос из `AllTestsSampleTest` возвращает правильное количество строк. Сейчас 18 проверок падают. После исправления всех багов `QuantitativeTest` должен проходить полностью.

**Промпт 81:** Исправь выполнение JOIN-запросов в движке. Сейчас любой `INNER JOIN` и `FULL JOIN` по условию ON возвращает 0 строк. Например, `SELECT USERS.ID, USERS.NAME, USER_DETAILS.INFO FROM USERS INNER JOIN USER_DETAILS ON USERS.ID = USER_DETAILS.USER_ID WHERE USERS.ID IN (500, 501, 502)` должен вернуть 3 строки, а возвращает 0. Для запросов, где в условии ON есть `OR` (например, `USERS JOIN PROFILES ON USERS.ID = PROFILES.USER_ID AND PROFILES.USER_ID > 0 OR PROFILES.USER_ID IS NOT NULL`), результат должен соответствовать перекрёстному произведению (600×600 = 360000 строк). Проверь результат по `QuantitativeTest`.

**Промпт 82:** Исправь GROUP BY: при группировке по столбцу с уникальными значениями движок возвращает 1 строку вместо числа групп. Например, `SELECT NAME, MIN(AGE), MAX(AGE), AVG(AGE) FROM USERS GROUP BY NAME` при 600 уникальных именах должен вернуть 600 строк, а возвращает 1. Группа должна создаваться для каждого уникального набора значений столбцов из GROUP BY. Проверь все GROUP BY-запросы из `QuantitativeTest`.

**Промпт 83:** Исправь оператор IN со списком значений: `SELECT ID, NAME FROM USERS WHERE AGE IN (50, 51, 52)` должен возвращать 21 строку, а возвращает 2. Проверь корректный разбор каждого значения в списке IN и фильтрацию по каждому из них.

**Промпт 84:** Исправь IN со списком строковых литералов в комбинации с AND/OR: `WHERE NAME IN ('User500', 'User501', 'User502') AND BALANCE > 5000` должен возвращать 0 строк, а `WHERE USER_CODE IN ('CODE500', 'CODE501', 'CODE502') OR BALANCE > 5000` — 3 строки. Сейчас условие игнорируется и возвращаются все 600 строк.

**Промпт 85:** Исправь LIMIT/OFFSET: `SELECT ID, NAME FROM USERS WHERE AGE = 50 OR BALANCE > 5000 LIMIT 10 OFFSET 5` должен возвращать 2 строки (после фильтра 7 строк, затем OFFSET 5, затем LIMIT 10), а возвращает 0. Также убедись, что `LIMIT 10` в запросах с подзапросами ограничивает результат (например, `WHERE AGE > (SELECT AGE FROM USERS WHERE ID = 500 LIMIT 1) LIMIT 10` должно возвращать не более 10 строк, а возвращает 600).
