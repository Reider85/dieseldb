## Что нужно добавить чтобы догнать и перегнать конкурентов

### 🔴 Критические недостатки (необходимо реализовать в первую очередь)

#### 1. **Переход на генератор парсеров** (Приоритет: ВЫСОКИЙ)
**Текущее состояние:** Ручной парсер на regex + string manipulation
**Цель:** ANTLR4 или JavaCC

**Преимущества:**
- Автоматическая генерация lexer/parser
- Гарантированная корректность грамматики
- Легкое добавление новых конструкций
- Снижение объема кода на 40-50%

**Пример грамматики ANTLR4:**
```antlr
selectStatement
    : SELECT selectItems FROM tableName (joinClause)* whereClause? groupByClause? havingClause? orderByClause? limitClause?
    ;

joinClause
    : (INNER | LEFT OUTER? | RIGHT OUTER? | FULL OUTER? | CROSS) JOIN tableName ON booleanExpression
    ;
```

**Ожидаемый эффект:** +25% к архитектуре, +15% к расширяемости

---

#### 2. **Построение AST (Abstract Syntax Tree)** (Приоритет: ВЫСОКИЙ)
**Текущее состояние:** Плоская структура Query objects
**Цель:** Полноценное дерево выражений

**Зачем нужно:**
- Оптимизация запросов (трансформация дерева)
- Валидация семантики
- Генерация планов выполнения
- Поддержка визитаторов

**Структура AST:**
```
SelectStatement
├── SelectItems
│   ├── ColumnRef("u.name")
│   └── AggregateFunction(COUNT, ColumnRef("*"))
├── FromClause
│   └── Table("users", alias="u")
├── JoinClause
│   ├── type: INNER
│   └── condition: BinaryExpression(...)
├── WhereClause
│   └── BinaryExpression(...)
└── OrderByClause
    └── SortItem(ColumnRef("name"), ASC)
```

**Ожидаемый эффект:** +30% к архитектуре, +20% к оптимизации

---

#### 3. **Cost-Based Optimizer (CBO)** (Приоритет: ВЫСОКИЙ)
**Текущее состояние:** Rule-Based (простые эвристики)
**Цель:** Статистический оптимизатор

**Компоненты:**
1. **Сбор статистики:**
   - Cardinality таблиц
   - Гистограммы распределения
   - Селективность предикатов
   
2. **Оценка стоимости:**
   ```java
   Cost = CPU_cost + IO_cost + Memory_cost
   CPU_cost = rows_processed * cpu_per_row
   IO_cost = pages_accessed * io_latency
   ```

3. **Генерация планов:**
   - Перебор порядков JOIN
   - Выбор типа сканирования (Index Scan vs Seq Scan)
   - Push down предикатов

**Ожидаемый эффект:** +50% к производительности сложных запросов

---

#### 4. **Поддержка CTE (Common Table Expressions)** (Приоритет: СРЕДНИЙ)
```sql
WITH RECURSIVE hierarchy AS (
    SELECT id, parent_id, 0 as level FROM nodes WHERE parent_id IS NULL
    UNION ALL
    SELECT n.id, n.parent_id, h.level + 1 
    FROM nodes n JOIN hierarchy h ON n.parent_id = h.id
)
SELECT * FROM hierarchy;
```

**Ожидаемый эффект:** +15% к полноте SQL

---

#### 5. **Оконные функции** (Приоритет: СРЕДНИЙ)
```sql
SELECT 
    name,
    salary,
    ROW_NUMBER() OVER (PARTITION BY dept ORDER BY salary DESC) as rank,
    LAG(salary, 1) OVER (ORDER BY hire_date) as prev_salary
FROM employees;
```

**Функции для реализации:**
- ROW_NUMBER, RANK, DENSE_RANK
- LAG, LEAD
- FIRST_VALUE, LAST_VALUE
- NTILE
- SUM/AVG/COUNT OVER (...)

**Ожидаемый эффект:** +20% к полноте SQL
