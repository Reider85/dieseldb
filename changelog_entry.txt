Fix ClassCastException when csv.table.mirror=on + csv.load.mode=auto_mtime

Root cause: Two writers (Table.saveToSerializedFile writes Table, CsvRowStorage.saveSerialized writes
SerializedTableData) shared the same .table extension. Database.loadTablesFromDisk() called
Table.loadFromFile() which unconditionally cast to Table, crashing on SerializedTableData with an
uncaught ClassCastException that propagated up and killed server startup (13 client-server test errors).

Changes:
- Table.loadFromFile(): detect object type (Table vs SerializedTableData) via instanceof;
  on SerializedTableData, create Table with correct schema from the data and delegate to
  storage.loadFromFile() which runs the auto_mtime path (shared fix for CSV + TSV)
- AbstractRowStorage.SerializedTableData: widened from protected to public with public fields
  (formatVersion, columns, columnTypes) for cross-package access from diesel.Table
- StorageLoadModeTest: @BeforeEach now pins csv.load.mode=file + tsv.load.mode=file (saves/restores
  previous values) so tests are independent of config.properties
- CompressionTest: added csv.load.mode/tsv.load.mode/csv.table.mirror/tsv.table.mirror to PROP_KEYS;
  @BeforeEach sets safe defaults to prevent auto_mtime+mirror from hijacking codec-fallback tests
- RegexPerformanceBenchmarkTest: threshold widened 30s -> 45s for CI load variability
- config.properties: defaults restored to csv.load.mode=file, csv.table.mirror=off (safe defaults;
  auto_mtime+mirror is opt-in)

Full suite: 341/0/0/0 BUILD SUCCESS
