3.0.86 Fix ServerConnectionLimitTest/SocketTimeoutTest failures + harden server startup against stale/corrupt table files

Changes:
- diesel/Database.java: Database.loadTablesFromDisk() now wraps each Table.loadFromFile() in try/catch(Exception) and logs a WARNING instead of letting an unhandled RuntimeException (DieselIOException from a stale/corrupt .table or mismatched CSV header) propagate up and kill the server thread during startup - the server now skips the bad table and starts cleanly
- diesel/Table.java: Table.loadFromFile() catch widened from IOException | ClassNotFoundException to Exception (a DieselIOException from the storage layer is a RuntimeException and previously escaped, crashing DatabaseServer.start() via loadTablesFromDisk); a failed load now logs a WARNING "Failed to load table X, creating empty" and returns the empty fallback table
- src/test/java/diesel/ServerConnectionLimitTest.java: start the server against a JUnit temp directory (diesel-conn-limit-test) instead of the project data/ dir so stale data\PROFILES.csv cannot trigger the load failure; temp dir removed in tearDown
- src/test/java/diesel/SocketTimeoutTest.java: same temp-dir isolation (diesel-socket-timeout-test)
- Root cause: ServerConnectionLimitTest/SocketTimeoutTest previously used the default Database() constructor (data dir = ./data); a leftover data\PROFILES.csv whose header no longer matches the persisted schema (CSV header columns missing from file (required by schema): [PROFILE_CODE, NON_INDEXED, PROFILE_DATE]) made CsvRowStorage.loadCsv -> CsvRowReader.buildColumnMapping throw DieselIOException, an unchecked exception the loader did not catch - the server thread died before the accept loop, failing both tests with "DieselIO Failed to load table from CSV file"
- Verification: isolated run ServerConnectionLimitTest,SocketTimeoutTest 2/2 green BUILD SUCCESS; quick suite green; full suite (4GB heap, @LargeTest) 360/0/0/0 BUILD SUCCESS (AllTestsSampleTest.prompt69Group timing flake elapsed 29995 ms vs 30000 ms was rerun green - this is unrelated 5 ms timer noise).
