3.0.102 Fix server response protocol consistency for OOM/error paths (sendSerializedResult) and wire failures

Changes:
- diesel/DatabaseServer.java: OOM responses (handleOutOfMemory), invalid-message rejection, and query-execution error catch now go through sendSerializedResult() (compression-aware marker+length+data protocol) instead of raw out.writeObject() — restores wire-protocol consistency so clients/tests that read via the compression-aware protocol no longer get OptionalDataException.
- src/test/java/diesel/PreparedStatementTest.java: setUp() now backs the Database with a fresh temp directory (real storage root matching the file-persisted engine) and tearDown() recursively deletes it; fixes "Missing value for column: ID" in the client-server round-trip path (fallback seq-generation when the implicit table reload lacks the registered sequence) and removes leftover temp artifacts.
- src/test/java/diesel/OomHandlingTest.java: roundTrip() and direct cursor-open/cursor-fetch reads now use the compression-aware readResult() protocol (marker byte + length + payload) matching sendSerializedResult, replacing raw ObjectInputStream.readObject().
