# Таблица необходимости типов данных для DieselDB

На данный момент DieselDB поддерживает следующие типы данных:

| Тип данных | Java класс | Статус |

| STRING | String.class | ✅ Реализовано |
| INTEGER | Integer.class | ✅ Реализовано |
| LONG | Long.class | ✅ Реализовано |
| SHORT | Short.class | ✅ Реализовано |
| BYTE | Byte.class | ✅ Реализовано |
| BIGDECIMAL | BigDecimal.class | ✅ Реализовано |
| FLOAT | Float.class | ✅ Реализовано |
| DOUBLE | Double.class | ✅ Реализовано |
| CHAR | Character.class | ✅ Реализовано |
| UUID | UUID.class | ✅ Реализовано |
| BOOLEAN | Boolean.class | ✅ Реализовано |
| DATE | LocalDate.class | ✅ Реализовано |
| DATETIME | LocalDateTime.class | ✅ Реализовано |
| DATETIME_MS | LocalDateTime.class | ✅ Реализовано |

## Детальная матрица приоритетов

### Критическая важность (Must Have - Q1-Q2 2025)

| Тип | Причина приоритета | Use Cases |
|-----|-------------------|-----------|
| JSON/JSONB | Современный стандарт, NoSQL возможности | Документоориентированные данные, гибкие схемы, API responses |
| ARRAY<T>| SQL стандарт, компактное хранение | Списки тегов, множественные значения, матрицы |
| TEXT/VARCHAR | Совместимость с PostgreSQL | Любые текстовые данные |
| TIMESTAMPTZ | Корректная работа с часовыми поясами | Глобальные приложения, аудит, логирование |
| VECTOR | AI/ML революция | Semantic search, рекомендации, similarity matching |
| ENUM | Целостность данных, производительность | Статусы, категории, фиксированные наборы |

### Высокая важность (Should Have - Q3-Q4 2025)

| Тип | Причина приоритета | Use Cases |
|-----|-------------------|-----------|
| GEOMETRY/GEOGRAPHY | Геоданные критичны для многих приложений | Карты, логистика, location-based services |
| TSVECTOR/TSQUERY | Полнотекстовый поиск | Поиск по документам, контенту |
| RANGE<T> | Валидация диапазонов, temporal queries | Периоды времени, ценовые диапазоны |
| INTERVAL | Работа с периодами времени | Расписания, дедлайны, повторяющиеся события |
| COMPOSITE | Структурированные данные | Адреса, координаты, сложные объекты |

### Средняя важность (Nice to Have - 2026)

| Тип | Причина | Use Cases |
|-----|---------|-----------|
| HSTORE | Альтернатива JSON для простых KV | Конфигурации, метаданные |
| CIDR/INET/MACADDR | Сетевые приложения | Логирование, безопасность, инвентаризация |
| LO (BLOB/CLOB) | Большие объекты | Файлы, изображения, документы |
| TIME_SERIES | Временные ряды | Мониторинг, метрики, IoT |

## Технические требования для реализации

### Для JSON/JSONB:
```java
// Требуется добавить:
- Класс JsonValue (обёртка над javax.json или Jackson)
- Поддержка операторов: ->, ->>, @>, ?, ?&, ?|
- GIN индексы для JSONB
- Функции извлечения путей
```

### Для ARRAY<T>:
```java
// Требуется добавить:
- Generic ArrayType<T> класс
- Синтаксис: column_name TYPE[], column_name TYPE[SIZE]
- Операторы: unnest, array_agg, array_cat, array_length
- Индексация элементов: array[1], array[1:3]
```

### Для VECTOR:
```java
// Требуется добавить:
- VectorFloat, VectorDouble классы
- Расстояния: L2, cosine similarity, inner product
- HNSW или IVF индексы для approximate nearest neighbor
- Операторы: <-> (L2), <=> (cosine), <#> (inner product)
```

### Для GEOMETRY/GEOGRAPHY:
```java
// Требуется добавить:
- Point, LineString, Polygon, MultiPoint, etc.
- Пространственные индексы (R-Tree, QuadTree)
- Функции: ST_Distance, ST_Intersects, ST_Contains, ST_Area
- Поддержка SRID/coordinate systems
```

### Для TIMESTAMPTZ:
```java
// Требуется добавить:
- OffsetDateTime или ZonedDateTime вместо LocalDateTime
- Конвертация между timezone при сохранении/чтении
- Функции: AT TIME ZONE, CURRENT_TIMESTAMP
```

## Выводы

### Минимальный набор для конкурентоспособности:
1. **JSON/JSONB** - критично для современных приложений
2. **ARRAY<T>** - стандарт SQL, необходим для нормализации
3. **VECTOR** - дифференциатор для AI эры
4. **TIMESTAMPTZ** - обязательно для production
5. **TEXT/VARCHAR** - базовая совместимость

### Киллер-фичи для превосходства над PostgreSQL:
1. **Native VECTOR** с оптимизированными индексами (быстрее pgvector)
2. **Native GEOMETRY** без внешних расширений
3. **Built-in TIME_SERIES** оптимизации
4. **Transparent ENCRYPTION** на уровне типов
5. **VERSIONED типы** для temporal queries out-of-the-box

### Рекомендация фокуса:
Для максимального эффекта при минимальных затратах сосредоточиться на:
1. JSON/JSONB (самый востребованный)
2. VECTOR (тренд AI/ML)
3. ARRAY<T> (SQL стандарт)
4. TIMESTAMPTZ (production ready)

Эти 4 типа дадут 80% ценности при 50% усилий.
